# 퇴직금 길잡이 화면 시안

퇴직금을 받기 전과 깨기 전에 정할 것을 돕는 서비스를, 실제로 눌러 볼 수 있는 PC 웹 화면으로 만든 설명용 시안이다.
실제 하나증권 홈페이지가 아니며 계좌, 금액, 날짜, 글귀는 모두 지어낸 값이다. 공모전에는 프로토타입을 낼 수 없고 `shots/`의 그림만 첨부할 수 있다.
이전 후보(수수료 비서) 시안은 `../prototype_수수료비서_보관/`에 있다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 (화면과 뒷단이 함께 뜬다)
```

- 주소: `#home`(내 퇴직금), `#account`(받을 계좌), `#papers`(회사에 낼 것), `#timeline`(일정), `#withdraw`(꺼내기 전), `#calc`(세금 계산기), `#alerts`(알림), `#agent`(길잡이가 한 일), `#log`(기록)
- 위 막대 "시연 도구": 퇴직금 입금시키기, 7일 지나게 하기, 처음 상태로
- 그림 다시 뽑기와 동작 점검(서버를 띄운 상태에서): `python3 scripts/shots.py`
- 검사: `npm run build` (타입 검사 포함)

## 시안 속 손님

31세, 근속 5년, 예상 퇴직금 1,500만 원. 세액공제용 IRP가 다른 금융사에 있고(손님이 동의해야 읽는다. 처음에는 연결되지 않은 상태다) 본인 납입 900만 원, 운용수익 90만 원이 들어 있다. 하나증권에는 IRP가 없다.

## 구성 (2026-11-26 뒷단을 층으로 나눠 다시 씀)

| 파일 | 내용 |
|---|---|
| `server/tax.ts` | 세금 셈과 법에서 정한 값. 퇴직소득세, 연금 수령 감면, 일부 인출 세금, 계산기, 인출 사유표. 상태를 모른다 |
| `server/store.ts` | 상태 한 벌과 그 모양(계좌, 사건, 제안, 알림, 대화, 실행 기록, 기록). 파일에 적고 다시 읽기 |
| `server/quote.ts` | 손님의 사건과 계좌로 셈하는 값: 받을 계좌 비교, 세 가지 경우, 일부 인출, 기한, 일정 |
| `server/case.ts` | 손님이 누르는 일. 단계 전환 표(`FLOW`)에 없는 전환은 막는다. 계좌 연결, 계좌 열기, 서류 내기, 해지, 할 일 표시 |
| `server/docs.ts` | 서류 준비: 계좌 확인 서류, 회사에 보내는 글, 과세이연계좌신고서, 상담 요약 |
| `server/monitor.ts` | 살피기: 지켜보는 조건 넷, 알림 채널과 켜고 끄기 |
| `server/agent/brain.ts` | 알아듣기. 말에서 뜻(여러 개)과 값(날짜·기간·금액·사유)을 뽑는다. 언어 모델이 맡을 자리이고 시안은 낱말 맞추기 |
| `server/agent/tools.ts` | 도구 11개(읽기·셈·준비·제안)와 할 수 없는 일 목록. 상태를 바꾸는 도구는 없다 |
| `server/agent/guard.ts` | 검사. 들어온 말이 권한 밖인지, 나가는 답에 도구가 셈하지 않은 금액이나 권하는 말이 섞였는지 |
| `server/agent/index.ts` | 한 번 답하는 순서(검사 → 알아듣기 → 도구 → 답 → 검사)와 실행 기록, 제안 받아들이기 |
| `server/view.ts`, `server/api.ts` | 화면이 그릴 값 한 벌, 주소 표 |
| `vite.config.ts` | 뒷단을 개발 서버의 `/api/*`로 올리고 상태를 임시 폴더 파일에 저장 |
| `src/App.tsx`, `src/Agent.tsx` | 틀과 길잡이 칸(대화, 제안 받아들이기, 실제 실행 순서) |
| `src/pages.tsx` | 내 퇴직금, 받을 계좌, 회사에 낼 것, 일정, 꺼내기 전 |
| `src/system.tsx` | 세금 계산기, 알림, 길잡이가 한 일(도구·권한·실행 기록), 기록(거르기, 내려받기) |

이번에 더한 기능: 다른 금융사 계좌 읽기 동의와 끊기, 길잡이의 제안을 손님이 받아들여야 실행되는 구조(사건 열기·내용 고치기·필요한 돈 적기·계좌 연결·상담 넘기기), 하나증권 IRP를 열어야 서류가 채워지는 순서, 회사에 보내는 글 복사, 손님이 챙길 일 목록, 법정 사유의 일부 인출 셈, 연금으로 받을 때의 세금, 세금 계산기, 알림 설정과 받은 알림, 실행 기록.

확인이 더 필요한 것(이번에 원문을 다시 열지 않고 넣은 값): 일부 인출 때 세금을 "꺼내는 만큼의 퇴직소득세"로, 부득이한 사유는 그 70%로 셈한 것. 섞인 계좌에서 퇴직금부터 꺼낸 것으로 본 것. 사유별 필요한 서류 이름. 기획서에 옮기기 전에 원문 대조가 필요하다.

## 지킨 원칙

- 금액은 길잡이가 만들지 않는다. 화면의 표와 길잡이의 표는 뒷단의 같은 셈(`quote.ts`, `tax.ts`)에서 나오고, 길잡이의 답은 보내기 전에 금액을 도구 결과와 대조한다.
- 길잡이는 상태를 바꾸지 못한다. 받을 계좌 고르기, 서류 냈다고 표시하기, 해지는 손님이 화면에서 누른다.
- 어느 쪽이 낫다고 권하지 않는다. 선택지는 처음에 아무것도 골라 두지 않는다.
- 해지에만 붙는 단계는 본인 인증 창 하나다. 말리는 글귀나 추가 화면은 없다.
- 퇴직급여 300만 원 이하와 근속 1년 미만은 대상이 아니라고 알린다.

## 사실과 가정

- 사실(하나증권 FAQ 469·470, 원문 확인): IRP는 금융사마다 한 사람에 한 계좌이고, 하나증권은 퇴직금용과 세액공제용을 한 계좌로 합쳐 둔다. 그래서 "따로 받기"는 세액공제용 IRP가 없는 금융사에 새로 여는 것으로 그렸다.
- 사실(FAQ 513·519·471): 일부 인출 불가, 퇴직금 입금은 영업점 처리 필요, 개설은 MTS에서 한다.
- 가정: 마이데이터로 다른 금융사 IRP의 재원 구분(본인 납입, 운용수익)까지 읽을 수 있다. 계좌 확인 서류를 웹에서 볼 수 있다. 해지 시 떼는 금액이 손님 화면에 나온다.
- 다른 금융사 계좌의 해지는 이 화면에서 실행하지 않는다. 정한 것만 기록한다.

## 계산 확인

퇴직소득세 식은 조사 노트(`research_notes/IRP 퇴직금 에이전트 근거 검증/퇴직소득세_IRP_세법.md`)의 예시와 맞췄다. 1,500만 원·5년 → 176,000원, 본인 납입 900만 원과 수익 90만 원의 16.5% → 1,633,500원. 홈택스 모의계산과의 대조는 아직 하지 못했다.

## 길잡이를 앞에 (2026-11-26)

- 첫 화면은 폼이 아니라 "상황을 한 문장으로 말해 주세요"다. 길잡이가 말에서 날짜·기간·금액을 뽑고 빠진 것만 되묻고, 알아들은 내용 카드에서 손님이 "이 내용으로 시작하기"를 눌러야 사건이 열린다(`server/core.ts`의 `intake`, `openDraft`).
- 사건이 열리면 첫 화면에 "누가 무엇을 하나요" 카드가 나온다(`whoDoesWhat`).
- 말에서 내용을 뽑는 부분은 낱말 맞추기다. "다음 달"은 30일 뒤로 잡는다.
- 그림: `shots/05_말로_시작하기.png`, `shots/home_사건.png`.
