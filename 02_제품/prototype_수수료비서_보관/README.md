# 수수료 비서 화면 시안

유료 주식정보 서비스 값을 손님에게 알리고 정리하게 돕는 서비스를, 실제로 눌러 볼 수 있는 PC 웹 화면으로 만든 설명용 시안이다.
실제 하나증권 홈페이지가 아니며 금액, 날짜, 종목, 글귀는 모두 지어낸 값이다. 공모전에는 프로토타입을 낼 수 없고 `shots/`의 그림만 첨부할 수 있다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 (화면과 뒷단이 함께 뜬다)
```

- 주소: `#home`(한눈에 보기), `#trades`, `#fees`, `#services`, `#rules`, `#log`
- 아래쪽 "시연 도구": 주문 체결시키기, 7일 지나게 하기, 처음 상태로
- 그림 다시 뽑기와 동작 점검(서버를 띄운 상태에서): `python3 scripts/shots.py`
- 검사: `npm run build` (타입 검사 포함)

## 구성

Vite + React 19 + TypeScript, 일반 CSS와 CSS 변수 토큰, 해시로 화면 전환, lucide 아이콘.

| 파일 | 내용 |
|---|---|
| `server/core.ts` | 뒷단 본체. 서비스·체결·알림·대화·기록 상태, 수수료 계산, 체결 직후 알림 조건, 비서의 물음 처리와 제안, 규칙, 되돌리기 |
| `vite.config.ts` | 뒷단을 개발 서버의 `/api/*` 주소로 올린다 |
| `src/App.tsx` | 대시보드 틀: 왼쪽 메뉴(상태 요약, 묶음별 메뉴), 위 막대(위치, 기준일, 비서 단추), 알림 토스트, 해지 확인 창, 시연 도구 |
| `src/pages.tsx` | 화면 여섯 쪽: 한눈에 보기(요약 타일, 영수증, 규칙 상태, 달별 막대, 최근 활동), 주문·체결, 수수료·서비스 값, 가입 서비스 관리, 알림 규칙, 활동 기록 |
| `src/Agent.tsx` | 오른쪽 비서 칸: 대화, 셈 내역, 제안 카드(손님 확인), 물음 입력 |
| `src/styles/` | 색·모서리·글꼴 토큰과 화면 스타일 |

## 구조를 정한 근거

- 형태는 대시보드다(응모자 지시, 2026-11-26). 하나은행 홈페이지 그림에서는 청록 강조색과 차분한 분위기만 가져오고 배치는 따르지 않는다. 한 번 그 배치를 그대로 따라 만들었다가 "너무 똑같다"는 지적을 받고 바꿨다.
- 응모자의 과거 사이트(직접 읽음): 조례영향 사이트의 머리 구조·경로 표시·페이지 머리말·토스트·확인 창·이력 화면, 금융 해커톤 사이트의 대시보드 틀(248px 왼쪽 메뉴와 상태 요약, 56px 위 막대, 본문 폭 1440px, 요약 타일 줄, 테두리 카드), 관광공사 사이트의 오른쪽 상담 칸.
- 애플 Human Interface Guidelines 원문 11쪽(2026-11-26 열람). 적용한 항목은 `03_에이전트/01_agent_design.md`의 표에 적었다.

## 시안의 한계

- 뒷단은 개발 서버 안에서 메모리로만 돈다. 서버를 끄면 처음 상태로 돌아간다. 실제 계좌·주문 시스템과 이어져 있지 않다.
- 비서의 "물음 알아듣기"는 낱말 맞추기다. 언어 모델을 쓰지 않았다.
- 하나증권의 상표·그림·홈페이지 배치는 쓰지 않았다.

## 확인하지 못한 가정

- 서비스 값이 국내주식 거래 금액 전체에 요율로 붙는다. 매매수수료와 서비스 값은 원 미만을 버린다.
- 하나증권 홈페이지에서 주문과 체결 알림이 되는지, 어떤 모양인지 보지 못했다.
- 주제 01의 예시는 "MTS 이용 편의성"이다. PC 웹 화면이 이 주제에 맞는지는 응모자가 판단하거나 주최 측에 물어야 한다.
- 손님 응답 없이 규칙으로 서비스를 쉬게 하는 것이 약관·규정상 되는지.
