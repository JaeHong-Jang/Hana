# AI 에이전트 설계: 퇴직금 받기 전·깨기 전 결정 도우미

- 작성일 2026-11-26. 짝 문서: `02_제품/02_service_definition_irp.md`, 근거: `reports/IRP 퇴직금 에이전트 근거 검증.md`.
- 설계는 모두 조사자 제안이다. 규제 판정의 절반은 당국 해석이 아니라 조사자 해석이다. 기획서 문장은 응모자가 직접 쓴다.
- 이전 후보의 설계(`01_agent_design.md`)에서 구조 다섯 부분과 "숫자는 에이전트가 만들지 않는다"는 원칙을 그대로 가져왔다.

## 먼저 짚을 것: 에이전트가 꼭 필요한가

다섯 결정 지점은 하나씩 떼어 놓으면 분기형 안내 화면으로 만들 수 있고, 금액 계산은 전부 규칙이다. 에이전트의 몫은 셋으로 좁힌다.

| 에이전트 몫 | 화면만으로 안 되는 까닭 |
|---|---|
| 상황을 듣고 해당하는 지점을 골라낸다 | 손님은 "다음 달 퇴사하는데 전세 잔금이 걸려 있어요"라고 말하지, 지점 이름을 고르지 않는다 |
| 지점들을 한 사건으로 잇는다 | 받을 계좌(입금 전) → 입금 → 꺼내기 전이 며칠에서 몇 달에 걸친다. 앞에서 답한 것을 뒤에서 다시 묻지 않는다 |
| 기한을 따라간다 | 지급 기한 14일, 현금 수령 뒤 60일, 입금 확인 |

입금 전에는 회사가 손님의 퇴사를 알기 어렵고, 입금 예정 퇴직금은 마이데이터 항목에 없다. 그래서 시작은 손님이 말을 거는 것이고 금액은 묻는다. 입금 뒤에는 입금 자체가 신호이므로 "입금 알림과 해지 화면의 세액 표시로 충분하다"는 반론이 강하다. 이 반론에는 절반만 답할 수 있다는 점을 숨기지 않는다.

## 에이전트가 화면에서 보이는 곳 (2026-11-26 추가)

에이전트가 옆에 붙은 질문 창으로만 보이지 않게, 시작과 진행을 에이전트가 맡는 것으로 그렸다.

| 곳 | 에이전트가 하는 일 | 손님이 하는 일 |
|---|---|---|
| 첫 화면 "상황을 한 문장으로 말해 주세요" | 말에서 퇴사일, 근속 기간, 퇴직금, 꺼낼 일을 뽑는다. 빠진 것만 하나씩 되묻는다. 알아들은 내용을 카드로 보여 준다 | 말한다. 카드가 맞으면 "이 내용으로 시작하기"를 누른다. 누르기 전에는 사건이 열리지 않는다 |
| 같은 답 안의 "정할 것" 목록 | 한 문장에서 해당하는 결정 지점을 골라낸다 | - |
| "누가 무엇을 하나요" 카드 | 읽기, 셈, 서류 준비, 기한 따라가기, 비교표 준비가 길잡이 몫으로 적힌다 | 받을 계좌 고르기, 본인 확인과 서류 내기, 마지막 결정이 손님 몫으로 적힌다 |
| 화면 안 점선 한 줄 | 지금 할 일과 알림을 먼저 건넨다 | - |
| 오른쪽 길잡이 칸 | 물음에 손님 금액으로 답하고 "어떻게 답했나요"로 쓴 도구를 보여 준다 | - |

폼은 없애지 않고 "말로 하지 않고 직접 넣기"로 접어 두었다. 길잡이가 멈춰도 화면만으로 끝까지 갈 수 있어야 하기 때문이다.

시안에서는 말에서 내용을 뽑는 일을 낱말 맞추기로 대신했다. 실제로는 이 부분을 언어 모델이 맡는다. 금액 셈과 상태 바꾸기는 그대로 정해진 함수가 맡는다.

## 시안에 구현한 구조 (2026-11-26 다시 짬)

앞선 시안은 물음 하나에 뜻 하나를 골라 미리 써 둔 답을 내는 구조였다. 아래로 바꿨다. 코드는 `02_제품/prototype/server/agent/`에 있다.

| 순서 | 하는 일 | 파일 |
|---|---|---|
| 1. 들어온 말 검사 | 상품·운용·대출 부탁, 대신 실행해 달라는 부탁이면 거절한다 | `guard.ts` |
| 2. 알아듣기 | 말에서 뜻(여러 개)과 값(퇴사일, 근속, 퇴직금, 필요한 돈, 사유)을 뽑는다. 언어 모델이 맡을 자리이고 시안은 낱말 맞추기다 | `brain.ts` |
| 3. 도구 실행 | 도구 11개(읽기 3, 셈 6, 준비 1, 제안 1)만 부를 수 있다. 부른 도구와 넣은 값, 받은 값이 실행 기록에 남는다 | `tools.ts` |
| 4. 제안 | 사건 열기, 내용 고치기, 필요한 돈 적기, 계좌 연결, 상담 넘기기는 제안으로 낸다. 손님이 받아들여야 실행된다 | `index.ts`의 `approve` |
| 5. 나가는 답 검사 | 답에 든 금액을 도구 결과와 손님 말에 나온 수와 대조한다. 없는 금액이나 권하는 말이 있으면 보내지 않는다 | `guard.ts` |

- 길잡이가 닿는 주소는 `ask` 하나다. 사건을 바꾸는 함수(`case.ts`)는 화면에서 손님이 눌렀을 때만 불린다.
- 살피기(`monitor.ts`)는 조건 넷(퇴사 3일 전 서류, 지급 기한, 입금, 60일)만 본다. 손님이 조건마다 켜고 끌 수 있다.
- 화면의 "어떻게 답했나요"와 "길잡이가 한 일" 쪽은 실행 기록을 그대로 보여 준다.
- 한계: 알아듣기가 낱말 맞추기라서 말을 조금만 바꿔도 놓친다. 언어 모델로 바꿔도 2번만 바뀌고 3~5번은 그대로라는 점이 이 구조의 요지다.

## 나누어 맡는 일 (다섯 부분)

| 부분 | 하는 일 | 언어 모델을 쓰는가 |
|---|---|---|
| 1. 살피기 | 퇴직급여 입금, 지급 기한 경과, 60일 남은 날을 정해진 조건으로 가린다 | 안 쓴다 |
| 2. 알아듣기 | 손님 말을 아래 아홉 가지 뜻으로 가르고, 빠진 정보(퇴사일, 금액, 필요액)를 되묻는다 | 쓴다. 이 부분만 |
| 3. 도구 | 계좌를 읽고, 세액과 기한을 셈하고, 선택지 카드를 만든다 | 안 쓴다 |
| 4. 문지기 | 누가 무엇을 하려는지 보고 허락되지 않은 것을 막는다 | 안 쓴다 |
| 5. 실행과 기록 | 손님이 누른 것만 진행하고, 손님이 본 비교표와 고른 것을 남긴다 | 안 쓴다 |

모델이 틀려도 금액이 틀리거나 손님 몰래 무엇이 바뀌지 않게 하려는 구조다. 금액은 도구가 낸 값만 쓰고, 화면의 표는 비서를 거치지 않는다.

## 사건의 상태

한 번의 퇴사가 "사건" 하나다. 사건은 아래 상태를 지난다.

| 상태 | 들어오는 조건 | 여기서 비서가 하는 일 | 다음 |
|---|---|---|---|
| 상황 듣기 | 손님이 말을 걸거나 "내 퇴직금"을 연다 | 퇴사일, 예상 퇴직금, 기존 IRP, 꺼낼 계획, 받은 방식(IRP·현금)을 묻는다 | 받을 계좌 정하기 / 60일 안내 |
| 받을 계좌 정하기 | 아직 입금 전 | 지점 1·4. 선택지 카드를 낸다 | 서류 준비 |
| 서류 준비 | 손님이 계좌를 골랐다 | 개설이 필요하면 휴대폰 연결, 계좌 확인 서류 준비 | 입금 기다리기 |
| 입금 기다리기 | 손님이 서류를 냈다고 표시 | 지급 기한을 따라간다. 지나면 알린다 | 입금 확인 |
| 입금 확인 | 살피기가 퇴직급여 입금을 본다 | 들어온 금액과 과세이연 처리를 보여 준다 | 닫힘 / 꺼내기 전 |
| 꺼내기 전 | 손님이 돈이 필요하다고 말한다 | 지점 2·5. 필요액을 되묻고 세 경우 비교표를 낸다 | 그대로 둠 / 해지 진행 / 상담 인계 |
| 60일 안내 | 이미 현금으로 받았다 | 지점 3. 남은 날과 낼 서류 | 입금 확인 / 닫힘 |
| 닫힘 | 손님이 결정을 끝냈다 | 기록을 남긴다. 다음 이직 때 다시 쓴다 | - |

## 알아듣는 뜻 아홉 가지

| 뜻 | 예 | 비서가 하는 일 |
|---|---|---|
| 퇴사 알림 | "다음 달에 퇴사해요" | 사건을 열고 빠진 정보를 묻는다 |
| 받을 계좌 | "IRP 있는데 거기로 받아도 돼요?" | 계좌 재원을 읽고 선택지 카드를 낸다 |
| 회사에 낼 것 | "회사에 뭘 내야 해요?" | 계좌 확인 서류와 낼 내용을 준비한다 |
| 입금 확인 | "퇴직금 들어왔어요?" | 입금과 과세이연 처리를 답한다 |
| 일부 필요 | "300만 원만 빼고 싶어요" | 일부 인출이 안 된다고 알리고 필요액·시점·사유를 묻는다 |
| 해지 세금 | "깨면 얼마 떼요?" | 원천징수 예정액을 읽어 답하고 셈 내역을 펼친다 |
| 현금 수령 | "통장으로 이미 받았어요" | 지급일을 묻고 60일 안내로 간다 |
| 운용·상품 | "뭐 사면 돼요?" | 다루지 않는다고 답하고 'AI 연금프로'나 상담으로 안내한다 |
| 그 밖 | - | 할 수 있는 일을 알려 준다 |

한 문장에 정할 것이 둘 이상 들어 있으면("다음 달에 퇴사하는데 전세 잔금 300만 원이 걸려 있어요") 뜻 하나로 가르지 않고, 해당하는 결정 지점을 모두 골라 목록으로 먼저 보여 준다. 시안에서는 이 경우 "어느 계좌로 받을지", "일부만 필요할 때", "꺼내는 사유: 전세·임차 보증금" 셋이 나온다. 에이전트 몫의 첫째(지점 골라내기)를 보여 주는 장면이다(2026-11-26 추가).

## 비서가 쓰는 도구

| 도구 | 종류 | 돌려주는 것 | 값의 출처 |
|---|---|---|---|
| 내 IRP 읽기 | 읽기 | 계좌, 재원(퇴직금·본인 납입·운용수익), 계속성 운용지시, 디폴트옵션 | 자사 기록 |
| 타사 연금 읽기 | 읽기 | 타사 IRP·DC 유무와 금액 | 마이데이터. 손님이 켠 경우만 |
| 해지 시 떼는 금액 읽기 | 읽기 | 전액 해지 시 원천징수 예정액 | 자사 기록(입금 뒤) |
| 퇴직소득세 모의계산 | 셈 | 입금 전 예상 세액과 셈 단계 | 손님이 넣은 금액·근속 + 정해진 식 |
| 섞임 계산 | 셈 | 본인 납입분과 수익에 붙는 16.5% | 자사 기록 |
| 기한 셈 | 셈 | 지급 기한, 60일 남은 날 | 손님이 넣은 날짜 |
| 인출 사유 대조 | 셈 | 사유별 "꺼낼 수 있는가"와 "세금이 낮은가" | 두 법령의 사유 표 |
| 선택지 카드 만들기 | 제안 | 받을 계좌 카드, 세 경우 비교표 | 위 도구들의 값 |
| 준비하기 | 준비 | 개설 화면 미리 채움과 휴대폰 연결, 계좌 확인 서류, 과세이연계좌신고서 초안, 상담 인계 요약 | - |

상태를 바꾸는 도구(개설 확정, 해지 실행)는 비서에게 주지 않는다. 손님이 화면의 단추를 누르고 본인 인증을 거칠 때만 바뀐다.

### 퇴직소득세 모의계산의 순서

1. 퇴직소득에서 근속연수공제를 뺀다(근속 5년 이하는 100만 원 × 근속연수).
2. 12를 곱하고 근속연수로 나눠 환산급여를 낸다.
3. 환산급여공제를 빼 과세표준을 낸다.
4. 기본세율을 적용한 뒤 근속연수를 곱하고 12로 나눈다.
5. 지방소득세 10%를 더한다.

근거는 소득세법 제48조·제55조이고, 구간별 공제표와 예시 여섯 건은 `research_notes/IRP 퇴직금 에이전트 근거 검증/퇴직소득세_IRP_세법.md`에 있다. 예시 두 건(600만 원·2년 → 70,400원, 1,500만 원·5년 → 176,000원)은 이 순서로 다시 셈해 맞는 것을 확인했다. 홈택스 모의계산과의 대조는 아직 못 했다.

입금 뒤에는 모의계산 대신 "해지 시 떼는 금액 읽기"의 확정 값을 쓴다.

## 움직이는 때

| 때 | 조건 | 비서가 하는 일 |
|---|---|---|
| 손님이 말을 걸 때 | 언제든 | 뜻을 가르고 사건을 열거나 잇는다 |
| 지급 기한이 지났을 때 | 서류를 냈다고 표시한 뒤 14일이 지나도록 입금이 없다 | 한 번 알린다. 회사에 물을 내용을 준비한다 |
| 퇴직급여가 들어왔을 때 | 자사 IRP에 퇴직급여 입금 | 금액과 과세이연 처리를 알린다. 열려 있는 사건이 없으면 사건을 새로 연다 |
| 60일이 줄어들 때 | 현금 수령 사건이 열려 있고 남은 날이 14일, 3일 | 남은 날과 낼 서류를 알린다 |
| 손님이 해지 화면에 들어설 때 | 비교표를 아직 안 봤다 | 비교표를 한 번 내민다. 건너뛸 수 있다 |

## 권한: 할 수 있는 일과 못 하는 일

| 일 | 손님 | 비서 |
|---|---|---|
| 계좌·금액 보기 | 직접 | 읽기 도구로 |
| 선택지와 금액 나란히 보이기 | - | 한다 |
| 받을 계좌 고르기 | 직접 누른다 | 고르지 않는다. "이쪽이 낫다"고 말하지 않는다 |
| IRP 개설 | 신분증 촬영, 본인 인증, 약관·설명 확인을 직접 | 화면을 미리 채우고 휴대폰으로 넘긴다 |
| 회사에 서류 내기 | 직접 낸다 | 서류를 준비한다 |
| 해지 | 직접 누르고 인증한다 | 비교표를 내밀 뿐, 말리지도 권하지도 않는다 |
| 운용·상품 추천, 대출 상품 연결 | - | 거절한다 |
| 전 직장·타 금융사에 신청 | 직접 | 못 한다 |

**대칭 원칙.** 그대로 두기와 해지하기는 같은 화면에서 고른다. 선택지는 처음에 아무것도 골라 두지 않는다. 해지에만 붙는 단계는 본인 인증 하나뿐이고, 말리는 글귀나 추가 화면은 넣지 않는다. 회사는 잔고가 남는 쪽이 이익이므로, 비서가 한쪽으로 기울지 않게 문지기가 "유지 권유 문구"와 "해지 단계 추가"를 막는다. 근거로 붙일 수 있는 것은 퇴직연금감독규정 제20조 제6호(해지를 부당하게 제한하는 약관 심사), 근퇴법 제33조 제1항(가입자를 위하여 성실하게), 금융분야 AI 가이드라인 6.1(자사 이익 우선 알고리즘을 이해상충 사례로 듦)이다.

**숫자는 비서가 만들지 않는다.** 금액과 날짜는 도구가 내고, 비서는 그 값을 말로 풀어 준다. 답마다 "어떻게 셈했나요"로 식과 출처 조문을 펼칠 수 있다.

## 틀렸을 때 어떻게 되는가

| 틀리는 곳 | 생기는 일 | 막는 장치 |
|---|---|---|
| 뜻을 잘못 가름 | 엉뚱한 지점을 안내한다 | 금액은 맞다. 고르는 것은 손님이 누른다. 가른 뜻이 "어떻게 답했나요"에 보인다 |
| 손님이 넣은 금액·근속이 틀림 | 입금 전 예상 세액이 어긋난다 | "예상"이라고 표시한다. 입금 뒤에는 자사 기록의 확정 값으로 바꾼다 |
| 모델이 금액을 지어냄 | 틀린 금액을 말한다 | 답에 넣는 금액은 도구가 준 값만 쓴다. 표는 비서를 거치지 않는다 |
| 인출 사유를 잘못 대조 | 꺼낼 수 있다고 잘못 안내한다 | 사유 대조 결과에는 "증빙 확인 필요"를 붙이고 상담 직원에게 넘긴다 |
| 비서가 멈춤 | 묻고 답하기가 안 된다 | 화면 여섯 쪽은 비서 없이도 다 된다. 알림 조건은 언어 모델을 쓰지 않는다 |

## 남기는 기록

기록 한 줄에는 때, 누가(손님·비서), 한 일, 손님이 본 비교표의 값이 들어간다. 손님이 비서의 카드에서 고른 일은 손님이 한 일로 남긴다. 금소법은 기록을 10년 보관하게 한다(제28조, 시행령 제26조).

## 예상 반론과 답할 재료

| 반론 | 답할 재료 | 약한 정도 |
|---|---|---|
| 화면 하나면 되지 않나 | 결정이 조건 조합으로 갈리고, 입금 전에는 손님이 말해야 시작되고, 며칠에 걸친다 | 중간~약함. 지점 하나하나는 화면으로 된다 |
| 법이 의무화하면 끝 아닌가 | 추진 중인 것은 수령 시점의 연금·일시금 비교다. 받을 계좌, 60일, 운용지시, 사유 차이는 그 밖으로 보인다(추론) | 중간. 개정안 조문을 확인하지 못했다 |
| 미래에셋이 이미 하지 않나 | 보도된 범위는 은퇴 수령 설계다 | 중간. 앱을 열지 못했다. "없다"고 쓸 수 없다 |
| 회사가 해지를 막으려는 것 아닌가 | 대칭 원칙, 유지율을 성과로 삼지 않음 | 강함 |
| 세금 상담이 되지 않나 | 자사가 뗄 원천징수 예정액과 모의계산에 머문다. 과세 체계 교육은 사업자 의무다 | 중간. 당국 해석이 없다 |
| 청년은 세금 차이가 작지 않나 | 맞다. 그래서 세금이 아니라 전액 해지 구조와 섞임을 보여 준다 | 강함(먼저 인정하는 답) |
| 하나증권 'AI 연금프로'와 무엇이 다른가 | 보도 기준으로 AI 연금프로는 운용 단계다. 이 서비스는 운용을 다루지 않고 넘긴다 | 앱 확인 전에는 쓸 수 없다 |

## 확인하지 못한 것

- 하나증권에서 퇴직금 계좌만 따로 해지할 수 있는지(지점 1의 성격이 바뀐다).
- 하나증권 웹에서 IRP 개설, 해지, 계좌 확인 서류 발급이 되는지.
- 손님 화면에 재원 구분과 해지 시 떼는 금액이 이미 보이는지.
- 20영업일 다수계좌 제한이 하나증권 IRP에 걸리는지. 걸리면 "지금 열 수 있는지 먼저 알려 준다"를 동작에 넣는다.
- 손님별 세액 표시가 세무사법 제2조 제4호의 상담에 해당하는지에 대한 당국 해석.
